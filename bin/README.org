=100755=. Non-executable libraries and data files are intentionally omitted.
The first column is machine-readable and should contain every executable
exactly once.

** Bibliography validation

Use =emacs-eval EXPRESSION= (or =--file FILE=) for ad-hoc agent calls into the
live session. It uses the existing socket-routing shim and never starts an
Emacs instance. The JSON response contains =ok=, a bounded Lisp =result=
summary, and =truncated=. Hash tables are described by their count without
traversing their contents; lists, vectors, nesting and strings have limits.
Export complete selected-entry data to a private UTF-8 file when required,
rather than treating a truncated response as complete data. =--timeout= bounds
only the client wait: a timeout leaves server execution uncertain and must not
trigger an automatic retry. Expensive parsing still belongs in clean batch
Emacs. =--socket-name= targets an explicitly selected existing test server.

=bib-entry-check --describe= prints the structural rules read directly from
[[file:../agents/bibliography-policy.md][the shared bibliography policy]]. Run
=bib-entry-check entries.json --parents parents.json= on exported JSON objects
or lists shaped as ={entrytype, key, fields}=. Field values must be decoded
strings, not serialized BibTeX entries. Omit =--parents= when there are no
crossrefs; =-= reads the primary input from stdin. Supplied parents are checked
as entries too. Missing parents, cycles and duplicate keys are explicit errors.

=--check-files= checks recorded attachments for nonempty regular files and PDF
headers. Relative paths require explicit =--file-root DIR= values. Missing
attachments are reported as absent; they are not proof that acquisition is
complete. No file is modified, and no network or Emacs request is made.

Exit 0 means structural checks pass; edition evidence, field relevance,
abstract quality and attachment identity/layout still require the separately
reported semantic review. Exit 1 means structural defects, and exit 2 means
the input or policy could not be checked. Unsupported date syntax is reported
for review rather than normalized or guessed; ordinary ISO dates, ranges and
labelled uncertainty are supported.

** Untrusted commands

=untrusted-run --workspace /absolute/new-output --read source=/absolute/input --
node /inputs/source/script.js= runs in the pinned Node 22.23.2 image, with
=/workspace= as its working directory. The output directory must not exist and
must be outside Google Drive. Inputs must not be credential/control paths,
symlinked roots/parents, or trees containing sockets/devices. Protected names are
checked throughout directory inputs, including agent account directories;
uninspectable trees are refused. Stage only the required files instead of
granting an ordinary repository root containing =.git= or credential files.
Only explicitly selected inputs are exposed: never grant a home directory, account configuration,
or credential store. Treat all output as untrusted, including symlinks.

Docker Desktop must already be running, with the reviewed Engine 29.1.3; other
engine versions are refused until the seccomp default is rebased and verified.
Provision the reviewed ARM64 image once:

#+begin_src sh
docker pull --platform linux/arm64 docker.io/library/node@sha256:8d342e46d3b2883df69f797cb60fc71d8a0b65de65ddfbf4bf63fdc02049615f
docker pull --platform linux/arm64 docker.io/library/python@sha256:bbc491ed39611eede47b1058ad4afb9ea957fb3bf4a7f1b442c6a5628ab93bdc
#+end_src

Select =--runtime python= for the pinned Python 3.11.16 slim-bookworm image.
The default remains =--runtime node=. Both use the same isolation restrictions;
arbitrary images are not accepted. Python dependencies must be supplied as
explicit read-only inputs and installed offline inside the container.

The runner refuses a missing image; it never pulls a mutable tag or falls back
to host execution. Both agents must use it for downloaded scripts, unfamiliar
repository builds/tests/install hooks, transient package runners, and execution
of extracted output. Pass minimal explicit inputs. If Docker, the pinned image,
or the required Linux runtime is unavailable, stop; do not retry on the host.
The paired =audit-mac-app= ASAR extractors also require this path. Their locked
dependency bootstrap runs before parsing; archive extraction itself has no network.

Reviewed local tools and code retain host execution; a repository's location
alone does not make its code trusted. Stage untrusted downloads and sources in
=~/.local/share/agent-untrusted/=. Paired guards deny
recognizable direct host launchers and execution involving
=~/.local/share/agent-untrusted=. These are routing checks, not a complete
analysis of arbitrary interpreter code. The host agent remains trusted and
full-access; only commands dispatched through the runner receive its VM boundary.

The container is non-root, drops all capabilities, forbids privilege escalation,
uses a read-only root filesystem, and receives no Docker/SSH sockets, host PID
namespace, terminal input, or ambient environment. Only fresh output is writable
on the host. Limits are 1 GiB memory, two CPUs, 64 processes, 64 MiB temporary
storage, 256 MiB per output file, and 120 seconds by default (600 maximum).
The host output directory has no aggregate disk quota; many files can still fill
disk. Container removal on completion/timeout kills daemonized descendants;
an unavailable Docker daemon can prevent confirmed cleanup and produces failure.

Native macOS Seatbelt was rejected after a synthetic =KERN_PROCARGS2= test read
another same-user process's argv/environment despite explicit deny rules. The
Linux VM avoids sharing that host process namespace. VM/kernel vulnerabilities,
unsafe explicit input grants, and subsequent execution of output remain risks.

=untrusted-run-seccomp.json= preserves the [[https://github.com/moby/moby/blob/fbf3ed25f893e6ce21336f1101590e40a13934f4/vendor/github.com/moby/profiles/seccomp/default.json][Docker Engine 29.1.3 default]]
(source SHA-256 =01536f1d1df938ae611eba20d6349e0de7a99b6ecdee1549427a0b01b8301e28=),
with only the [[https://github.com/moby/profiles/commit/dec315c57e60de0ffb1e07485815eb71d7b820e8][upstream AF_ALG socket restriction]] added. It still denies
AF_VSOCK and defaults to =SCMP_ACT_ERRNO=; no general syscall permissions were
broadened. This modified Moby resource is covered by
[[file:untrusted-run-seccomp.LICENSE][Apache License 2.0]]. Re-review its upstream default when upgrading the engine;
do not replace it with a permissive custom profile. Runtime-image provenance:
[[https://hub.docker.com/_/node][Docker Official Node image]] and
[[https://hub.docker.com/_/python][Docker Official Python image]].

* Regenerating the inventory

The exact source list is:

#+begin_src sh
git ls-files -s bin | awk '$1 == "100755" {sub(/^bin\//, "", $4); print $4}'
#+end_src

When an executable is added, removed, or changes mode, update this table in the
same commit. Derive the inventory from Git rather than walking untracked files.
