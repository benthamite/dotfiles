#+title: Codex hook implementations
#+author: Pablo Stafforini

* Activation and boundaries

The tracked [[file:../hooks.json][hooks.json]] file registers Codex hooks and is live globally through
the =~/.codex/hooks.json= symlink. Registration and implementation are separate:
the JSON chooses an event and matcher, while the scripts in this directory
decide what to block, record, regenerate, or report. Six =lib-*= files are
sourced helpers rather than registered hooks. =session-learning-capture.sh= is
a retained legacy helper and is not registered at present.

These hooks supplement the written instructions with executable checks. An
allowing result from one hook does not bypass another hook, the global rules,
or the need for user authorization.

* Operational contracts

The security guards for secrets, sensitive reads, destructive commands,
GitHub writes, paid Ahrefs access, dirty-tree rewrites, LaunchAgents, and
walk-list data convert unexpected failures to blocking exit code 2. Their
dependency-free handler is installed before external commands, and required
source files fail explicitly even on macOS Bash. Ordinary successful checks
retain their allow/deny decisions and never introduce approval prompts.

The secret guard scans =Write.content= and =Edit.new_string= as well as patch
text. The Claude counterpart also covers notebook cell source.

The destructive-command guard is registered directly here. Claude carries the
same logic inline in its =pretooluse-bash.sh= dispatcher, so both implementations
must change and be tested together. Decisions are allow or deny, never approval
prompts; =ALLOW_CLONE=1= is the narrow explicit clone override.

The dirty-tree rewrite guard blocks =filter-repo= and =filter-branch= only when
the target repository has staged or unstaged tracked changes. Untracked files
are deliberately ignored. It resolves =git -C= and the last applicable =cd=
before falling back to the hook working directory, and masks heredoc bodies to
avoid prose false positives. =ALLOW_DIRTY_REWRITE=1= is the explicit override.

The sensitive-read guard denies content access to credential-bearing paths. It
permits content-free metadata, quiet/count/name-only searches, existence tests,
Git ignore/index queries, and auth-aware tools only in recognized narrow forms.
The classifier recognizes =pass=, =git-crypt=, =security=, =op=,
=op-automations=, and =op-desktop= as auth-aware tools; the independent
secret-leak guard still denies their secret-printing shapes. It also permits
=.env= or =.envrc= to be sourced solely as subprocess environment, and
=op-automations run --env-file .env.op -- <program>= with leading =VAR=value=
assignments and file redirects, while still denying commands that print,
parse, or dump that environment.

The secret-leak guard applies the same command policy to every literal nested
=cmd= inside a =functions.exec= program, including nested shell-tool calls; a
1Password broker named anywhere else in the program is denied as
unclassifiable. Raw =op=, =pass=, =security=, and =pbpaste= are denied even
when wrapped, piped, filtered, redirected, dynamically resolved, or called
through a literal nested shell. The brokers =op-automations= and =op-desktop=
are classified by =lib-op-policy.py=, an allowlist of command shapes whose
stdout carries no credential: masked =run= with a non-shell program, =read=
captured into a variable, a regular file, or a listed consumer, item output
piped to a metadata-only =jq= filter or a file, =document get=/=inject= with
=--out-file=, writes without =--format=, and metadata commands. Every other
broker shape is denied, including =--reveal=, =item share=, =signin=,
=environment read=, credential-minting subcommands, indirection, and any
=OP_*= environment override. Quoted literals in ordinary commands and simple
non-expanding =echo=/=printf= documentation remain available. The case table
is =tests/test_op_policy.py=.

The GitHub write guard is deny-only. It refuses writes outside the committed
repository registry, but a matching repository establishes only that boundary;
the hook emits no explicit allow, including for pull-request merges. Authorized
writes continue through the host's normal permission layer and still require the
user authorization called for by the global instructions.

The Elisp commit gate routes each literal nested =tools.exec_command= call by
its own =workdir=, groups staged and commit calls by repository, inherits an
omitted workdir from the outer context, and denies dynamic or ambiguous commit
targets. The post-commit tracker uses the same context and recognizes Git
global options such as =-C=. Multiple commits inside one shell call remain
distinct. Inert quoted text and shell comments do not count as commits, while
interpreter payloads remain conservative. Only evidence whose label matches
exactly one supported wrapper in executable position, with no other executable
in that command event, can clear an obligation.

Elisp test and live evidence includes a one-time correlation receipt. The
tracker binds the evidence label to the observed wrapper arguments and
atomically consumes the receipt. A receipt can clear one matching event, and a
second use fails. A textual mention, mismatched label, or compound output
command does not count as the wrapper event. This is not authentication against
another process running as the same user: such a process can source the public
issuer or write the user-owned state files. On the next issue or consume
operation, the helper removes only user-owned regular receipt and claim files
older than one day. It never expires or removes test markers or
live-verification obligations.

The Elisp documentation gate honors
=branch.<branch>.deferDocUpdates=true= only on feature branches and ignores it
on =main= and =master=. Remove the setting when the branch merges.

The hook installer owns all eight =codex-hook-wrapper= lifecycle registrations.
It must preserve the live =config.toml= and =hooks.json= symlinks and replace
stale profile-specific wrapper paths rather than append duplicates. The global
wrappers are safe outside Emacs: when =CODEX_BUFFER_NAME= is absent, they
consume the payload and exit successfully without calling =emacsclient=.

=require-codex-readme-update.sh= is a dotfiles-scoped commit gate. Its
command-text fallback excludes project-local =.codex/= paths, and it excludes
the repo-root =AGENTS.md= project mirror; the project-local dotfiles skill is
handled by its configured documentation owner instead.

The LaunchAgent registry guard routes every launchd change through
=~/repos/launchd=. It denies writing a plist into
=~/Library/LaunchAgents=, redirecting into that directory, and
=launchctl bootstrap/load/enable/submit= as well as
=bootout/unload/disable/remove=, and names =bin/launchd-install.py= in the
denial. That script writes the canonical plist, symlinks the live file, adds the
=registry/jobs.json= entry, and runs the drift audit; loading stays behind its
explicit =--load= flag. Read-only inspection is deliberately untouched: =ls=,
=cat=, =readlink=, =diff=, =plutil -p=, =defaults read=, and =launchctl
print/list=. Heredoc bodies are masked so a commit message quoting a live path is
not read as an invocation. =ALLOW_LAUNCHAGENT_CHANGE=1= is the narrow override
for a change Pablo has authorized, such as a temporary bootout while debugging.

| =block-elpaca-dotfiles-edit.sh= | Denies writes to the read-only Elpaca dotfiles mirror and points to the canonical repository. |

Read-only inspection remains allowed. Nested =functions.exec= shell calls are checked independently and ambiguous recognized calls fail closed. |
| =block-secret-leak.sh= | Blocks literal secret disclosure and unsafe secret-bearing reads, writes, or output. |

The documentation audit requires every tracked direct child to appear exactly
once in this table. After changing a registered hook, verify the registration
and exercise the relevant allow and deny paths; running the script in isolation
does not prove that Codex invokes it with the intended event payload.
