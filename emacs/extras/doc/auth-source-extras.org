This manual describes the features and customization options for the Emacs Lisp file =auth-source-extras.el=.

* Overview
:PROPERTIES:
:CUSTOM_ID: h:overview
:END:

=auth-source-extras.el= reads secrets that Emacs needs without a person present, such as API keys and tokens, from a 1Password vault named "Automation" ("Automations" in the Epoch account). Each 1Password account has its own Automation vault and a read-only service account that can read nothing else. The service account's token is stored in the macOS login Keychain and read by the =op-automations= wrapper, so reads never prompt while you are logged in, and a leaked token exposes only that one vault.

* Reading secrets
:PROPERTIES:
:CUSTOM_ID: h:reading-secrets
:END:

#+findex: auth-source-extras-op-get
~auth-source-extras-op-get~ returns one field of one item: =(auth-source-extras-op-get ITEM FIELD ACCOUNT)=. ITEM is the item title, FIELD a field label or ID such as ="credential"= or ="password"=, and ACCOUNT an account symbol such as =personal= or =tlon=, defaulting to =personal=. For example, =(auth-source-extras-op-get "openai.com" "credential" 'tlon)= reads the Tlon OpenAI key.

The first request for an account fetches the requested item together with every item listed for that account in ~auth-source-extras-op-prefetch~. Each item is fetched by its own CLI process and all of them run in parallel, since a single =op= invocation fetches items one after another. Fetched items stay in memory for the rest of the session, so later reads are instant and a session makes one round of requests per account.

If an item cannot be read, for example because the account has no token in the Keychain or the item does not exist, the function returns nil and displays one warning per distinct reason, naming the affected items. The reason is the last line of the CLI's own error output, such as ="mbsync/password" isn't an item in the "Automation" vault= or =no token in the Keychain for op-service-account/tlon-automation=; it never contains item values. This lets a shared configuration load on machines that can read only some of the accounts.

#+findex: auth-source-extras-op-clear-cache
~auth-source-extras-op-clear-cache~ forgets every cached secret and vault listing, so the next read fetches fresh values, for example after rotating a key.

Field IDs take precedence over display labels. Empty template labels are ignored, so duplicate labels such as =password= cannot hide the actual password field.

Results are accepted only when the returned item's title matches the requested one exactly. When no item has a given title, the CLI can return another item whose website matches it, and that would hand out the wrong secret.

* Unlocking git-crypt repositories
:PROPERTIES:
:CUSTOM_ID: h:git-crypt
:END:

#+findex: auth-source-extras-git-crypt-unlock
~auth-source-extras-git-crypt-unlock~ unlocks the =git-crypt= repository in the current directory with a key stored as a Document item in the Tlon Automation vault. Called interactively, it offers the titles of that vault's documents. The binary key is written by the CLI straight to a private temporary file, byte for byte, passed to =git-crypt unlock=, and deleted whatever the outcome. From Lisp, =(auth-source-extras-git-crypt-unlock REPO KEY ACCOUNT)= also accepts another account.

* The auth-source backend
:PROPERTIES:
:CUSTOM_ID: h:backend
:END:

#+findex: auth-source-extras-op-search
Adding the symbol =1password-automation= to ~auth-sources~ makes generic ~auth-source-search~ lookups, such as the GitHub tokens used by Forge and Magit or the SMTP password, read from the Automation vaults. The backend looks for items titled =HOST/USER=, =USER@HOST=, =HOST:PORT/USER=, =HOST:PORT= and =HOST=. A bare =HOST= title matches only if its stored =username= field, when it has one, is among the requested users. The backend searches accounts in order and uses cached items before listing a vault. It stops once enough credentials are found, so a cached SMTP password needs no vault requests. Successful vault listings are cached; failed listings warn and are retried on the next lookup. Other accounts and authentication backends remain available when a vault cannot be listed. A known, more-specific item retains precedence over a cached generic credential. Entries without a nonempty password are not returned. Requests that allow credential creation can still retrieve existing entries, but the backend cannot create or delete entries.

* Customization
:PROPERTIES:
:CUSTOM_ID: h:customization
:END:

#+vindex: auth-source-extras-op-prefetch
~auth-source-extras-op-prefetch~ lists, per account, the item titles to fetch together on first use. List every item the configuration reads at startup.

#+vindex: auth-source-extras-op-vault
~auth-source-extras-op-vault~ names the vault the service accounts can read, ="Automation"= by default.

#+vindex: auth-source-extras-op-account-vaults
~auth-source-extras-op-account-vaults~ maps accounts whose automation vault has another name to that name. By default it maps =epoch= to ="Automations"=, so =(auth-source-extras-op-get ITEM FIELD 'epoch)= reads Epoch's Automations vault.

#+vindex: auth-source-extras-op-program
~auth-source-extras-op-program~ is the service-account wrapper, =op-automations= by default. It is called as =op-automations @ACCOUNT ...= and reads that account's token from the login Keychain (=op-service-account/ACCOUNT-automation=) itself, so no read can prompt.

#+vindex: auth-source-extras-op-search-accounts
~auth-source-extras-op-search-accounts~ lists the accounts the =auth-source= backend searches, in order: =personal=, then =tlon=.

#+vindex: auth-source-extras-op-timeout
~auth-source-extras-op-timeout~ is how many seconds to wait for a batch of fetches before giving up on the items still pending.

* Setting up a machine
:PROPERTIES:
:CUSTOM_ID: h:setup
:END:

An account admin creates one read-only service account per person and machine, with access only to that account's Automation vault, and hands its token over through 1Password. The recipient stores it in the login Keychain under the service name =op-automations= expects, for example with =security add-generic-password -U -a "$USER" -s op-service-account/tlon-automation -w TOKEN=.
