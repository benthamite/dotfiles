#+title: Claude helper commands
#+author: Pablo Stafforini

* Activation and scope

This directory contains Claude-specific service wrappers, test runners, and
configuration installers. There is no =~/.claude/bin= link, and the directory is
not an executable root by itself. Agent instructions and other scripts invoke
these files by their repository paths. A similarly named command elsewhere on
=PATH= is not evidence that the tracked file is active.

* Operational boundaries

=ai-provider-key= keeps provider administrator credentials out of project
repositories and stores project-scoped runtime credentials in the Automations
vault. Non-dry operations require a current, authorized spend-control assertion
within the retained helper ceiling; the helper neither reads live limits nor
enforces per-key budgets. Pure dry-run mode prepares metadata without account
access. Provisioning preflights local/item conflicts, uses broker stdin for
secret writes, and compares exact readback before wiring an immutable item
reference. Provider, vault and local-file changes are not one transaction;
reconcile an uncertain attempt before retrying or replacing a credential.

=slack.py= uses the selected operator's browser session, not an automation bot.
Its Epoch credential path uses =op-automations=; credential-bearing API/file
requests refuse redirects and omit response payloads from failure diagnostics.
Success payloads can still contain private data or newly created app secrets:
callers must capture and selectively consume them, not print them wholesale.

=ahrefs-api-guard= probes the free subscription-usage endpoint before every
paid request. It requires a positive conservative =--estimated-cost= and valid
workspace/API-key quota, then compares the projected balance with the configured
reserve and key allowance. This preflight is not an atomic reservation or hard
spending ceiling. Manual Ahrefs calls must use the guarded command; a similarly
named PATH wrapper should not be assumed to be this tracked file without
resolving it.

=copy-slack-draft= requires the intended existing Emacs =--socket= and a private
UTF-8 draft file outside Drive. It opens the exact Epoch destination, preserves
conflicting unsent input, verifies composer insertion, then stages the same text
in the kill ring without importing or exporting the system clipboard.
=--open-only= opens without copying or inserting. Structured receipts distinguish
acknowledged stages from uncertain outcomes; private recovery snapshots survive
uncertainty. Raw request errors and draft contents are omitted from diagnostics.

The documentation audit requires every tracked direct child to appear exactly
once in this table. Several wrappers obtain credentials from external stores or
perform remote writes. Inspect the requested account and operation before use,
and never invoke a credential path merely to verify this index.
