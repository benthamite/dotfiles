This manual describes the features and customization options for the Emacs Lisp file =auth-source-extras.el=.

* Overview
:PROPERTIES:
:CUSTOM_ID: h:overview
:END:

=auth-source-extras.el= reads secrets that Emacs needs without a person present, such as API keys and tokens, from a 1Password vault named "Automation". Each 1Password account has its own Automation vault and a read-only service account that can read nothing else. The service account's token is stored in the macOS login Keychain, so reads never prompt while you are logged in, and a leaked token exposes only that one vault.

* Reading secrets
:PROPERTIES:
:CUSTOM_ID: h:reading-secrets
:END:

#+findex: auth-source-extras-op-get
~auth-source-extras-op-get~ returns one field of one item: =(auth-source-extras-op-get ITEM FIELD ACCOUNT)=. ITEM is the item title, FIELD a field label or ID such as ="credential"= or ="password"=, and ACCOUNT a key of ~auth-source-extras-op-accounts~, defaulting to =personal=. For example, =(auth-source-extras-op-get "openai.com" "credential" 'tlon)= reads the Tlon OpenAI key.

The first request for an account fetches the requested item together with every item listed for that account in ~auth-source-extras-op-prefetch~. Each item is fetched by its own =op= process and all of them run in parallel, since a single =op= invocation fetches items one after another. Fetched items stay in memory for the rest of the session, so later reads are instant and a session makes one round of requests per account.

If an account has no token in the Keychain, or an item does not exist, the function displays a warning once and returns nil. This lets a shared configuration load on machines that can read only some of the accounts.

#+findex: auth-source-extras-op-clear-cache
~auth-source-extras-op-clear-cache~ forgets every cached secret and token, so the next read fetches fresh values, for example after rotating a key.

* Customization
:PROPERTIES:
:CUSTOM_ID: h:customization
:END:

#+vindex: auth-source-extras-op-accounts
~auth-source-extras-op-accounts~ maps each account symbol to the name of the Keychain generic password holding its service-account token. The defaults are =personal= (=op-service-account/personal-automation=) and =tlon= (=op-service-account/tlon-automation=).

#+vindex: auth-source-extras-op-prefetch
~auth-source-extras-op-prefetch~ lists, per account, the item titles to fetch together on first use. List every item the configuration reads at startup.

#+vindex: auth-source-extras-op-vault
~auth-source-extras-op-vault~ names the vault the service accounts can read, ="Automation"= by default.

#+vindex: auth-source-extras-op-program
~auth-source-extras-op-program~ is the path to the 1Password CLI. It must be the CLI itself, not a wrapper that routes requests through the desktop app, because service-account requests must never prompt.

#+vindex: auth-source-extras-op-timeout
~auth-source-extras-op-timeout~ is how many seconds to wait for a batch of fetches before giving up on the items still pending.

* Setting up a machine
:PROPERTIES:
:CUSTOM_ID: h:setup
:END:

An account admin creates one read-only service account per person and machine, with access only to that account's Automation vault, and hands its token over through 1Password. The recipient stores it in the login Keychain under the service name configured in ~auth-source-extras-op-accounts~, for example with =security add-generic-password -U -a "$USER" -s op-service-account/tlon-automation -w TOKEN=.
