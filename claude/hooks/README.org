#+title: Claude hook implementations
#+author: Pablo Stafforini

The closed Python document-edit classifier permits =update= statements on bound
JSON data with one validated dictionary literal and no keyword arguments.
A mutation alone does not satisfy its required document write.

Literal Python-file writers have a separate closed shape: one literal path and
source, an optional existence guard, mode =0600=, and path-only print. The
generated source is parsed with both writer exemptions disabled. Credential
references, unknown calls and additional writes remain denied.

* Activation and boundaries

Claude's global hook registration lives in the mutable
=~/.claude/settings.json= file. It invokes selected scripts here by absolute
path; there is no =~/.claude/hooks= directory link. The tracked
=ai-config-sync.json= manifest owns and audits the paired hook inventory.

Not every file below is a global event registration. Some are sourced helpers,
dispatch targets, one-shot installers, compatibility wrappers, or project-local
guards. Registration determines when a script runs; its presence in this
directory does not.

* Operational contracts

The Bash dispatcher delegates =block-untrusted-execution.sh= to the paired
=lib-untrusted-execution.py= classifier. It denies recognizable transient
package runners, downloaded interpreter input, and host execution involving
=~/.local/share/agent-untrusted/=. Plain source inspection and package metadata
remain available. The canonical =bin/untrusted-run= command is allowed per
invocation; its host substitutions and following commands remain checked.
Quoted data heredocs are distinguished from shell commands. Unsupported
relevant shell forms deny without an approval prompt. This is bounded routing,
not arbitrary-program analysis or an independent same-user security boundary.
The VM runner supplies the execution boundary. Synthetic hook decisions are
covered by =tests/test_untrusted_execution_guard.py=.

The Bash dispatcher and security guards for secrets, sensitive reads,
destructive commands, paid Ahrefs access, dirty-tree rewrites, LaunchAgents,
and walk-list data convert unexpected failures to blocking exit code 2.
Their dependency-free handler is installed before external commands; required
source files also fail explicitly, because macOS Bash can report a failed
source as status zero inside an EXIT trap. Ordinary successful checks retain
their allow/deny decisions and never introduce approval prompts.

The secret guard scans new content from =Write=, =Edit=, and =NotebookEdit=,
including replacement text and notebook cell source. Removing an existing
secret does not require copying it into the replacement text. Each native call
has one destination; the =Write= secret-file exception remains unchanged.
Codex separately classifies each destination in its multi-file patches.

The destructive-command policy is registered as a standalone Codex hook but is
inlined into Claude's =pretooluse-bash.sh= dispatcher. Change and test those two
implementations together. Both are deny-only and never ask for approval;
=ALLOW_CLONE=1= is the narrow explicit override for an otherwise blocked clone.

The dirty-tree rewrite guard blocks =filter-repo= and =filter-branch= only when
the target repository has staged or unstaged tracked changes. Untracked files
are deliberately ignored. It resolves the target from =git -C=, the last
applicable =cd=, and then the hook working directory, while masking heredoc
bodies to avoid treating quoted examples as commands. =ALLOW_DIRTY_REWRITE=1=
is its explicit override.

The sensitive-read guard denies content access to credential-bearing paths.
It permits content-free metadata commands, quiet/count/name-only searches,
existence tests, Git ignore/index queries, and auth-aware tools only within the
narrow forms recognized by the hook; a compound command cannot inherit an
allowance from a safe first command. The sensitive-path classifier recognizes
=pass=, =git-crypt=, =security=, =op=, =op-automations=, and =op-desktop= as
auth-aware tools; the independent secret-leak guard still denies their
secret-printing shapes. Sourcing a quoted or unquoted =.env= or =.envrc=
solely as subprocess environment is allowed, including =set -a= wrappers, and
so is =op-automations run --env-file .env.op -- <program>= with leading
=VAR=value= assignments and file redirects (1Password reads the file and
masks the values); printing, parsing, or dumping that environment is denied. Claude
registers the standalone hook for =Read= and =Grep= and keeps its Bash logic
inlined in =pretooluse-bash.sh=. Grep content searches remain available for
ordinary repository scopes and filename/count-only searches; sensitive paths,
globs, and broad home-directory content searches are denied.

The secret-leak guard blocks secret-shaped literals and secret-printing
commands. Raw =op=, =pass=, =security=, and =pbpaste= are denied even when
wrapped, piped, filtered, redirected, dynamically resolved, or called through
a nested shell. The 1Password brokers =op-automations= and =op-desktop= are
classified by =lib-op-policy.py=, an allowlist of command shapes whose stdout
carries no credential: masked =run= with a non-shell program, =read= captured
into a variable, a regular file, or a listed consumer, item output piped to a
metadata-only =jq= filter or a file, =document get=/=inject= with
=--out-file=, writes without =--format=, =op-desktop item share= restricted
with =--emails=, and metadata commands. Every other broker shape is denied,
including shapes the classifier cannot place, a broker named inside an
interpreter program or reached through indirection, =--reveal=, share links
without =--emails=, =signin=, =environment read=, credential-minting
subcommands, and any =OP_*= environment override. Quoted literals in ordinary
commands and simple non-expanding =echo=/=printf= documentation remain
available. Interpreter source is never parsed as shell text: a Python
heredoc naming a broker is denied unless =lib-python-heredoc.py --brokers=
recognizes it as a pathlib document edit, and any other interpreter program
(=node= heredoc, =python3 -c=, =perl -e=…) naming a broker is denied, since
a string and a =subprocess= call look alike. The case table is
=tests/test_op_policy.py=; the rationale is
=docs/superpowers/plans/2026-09-02-secret-guard-op-output-policy.md=.

The secret heuristic normalizes the exact public dated-upload prefix at
=myweb.sabanciuniv.edu/ozgurkibris/files/YYYY/MM/= before testing opaque
strings. It retains filenames, additional paths, queries, fragments, headers
and request bodies. Other authors, private routes and lookalike authorities
receive no exemption. =tests/test_secret_guard_parity.py= checks the actual
public-PDF command and secret-bearing negative controls across both runtimes.

Public routing is classified by =lib-public-url-scan.py=, whose declarative
registry covers only verified authority/schema pairs. Only URL operands of
recognized literal =curl=/=wget= commands receive routing projections;
unknown command forms retain the conservative opaque-token scan. Headers,
bodies, filenames and URL tails remain scanned, including bounded percent
decoding. Denials identify the field and rule without printing suspect bytes.
This does not exempt every public PDF or replace known-secret checks on the
original command. =tests/test_public_url_scan.py= pins the parser boundaries.

The quote-aware network parser classifies literal =curl=/=wget= output-file
options itself. A quoted URL query containing =&= cannot turn its separate local
destination into a network payload. URI-shaped output values, headers, bodies,
URLs and unknown command forms remain scanned; known-secret checks still inspect
the complete original command.

Literal newline command separators and backslashes inside single quotes are
parsed without evaluating shell text. Literal =mkdir -p= absolute directories
are local destinations when no pipeline can forward diagnostic output.
Expansions, unquoted or double-quoted escapes, and unknown command forms retain
conservative scanning.

The [[https://github.com/internetarchive/wayback/tree/master/wayback-cdx-server][Wayback CDX API]]'s single =url= target and HTTPS =web.archive.org/web/=
replay URLs with a 14-digit timestamp and optional =id_= flag are parsed as
archive envelopes. Their embedded targets still pass the ordinary URL checks;
malformed decoded targets and nested archive envelopes receive no exemption.
Other query fields, fragments,
headers and bodies remain scanned. Two exact verified Matuschak note IDs
(=Daily working log= and =My morning writing practice=) are registered from
the [[https://web.archive.org/web/20200812125852/https://notes.andymatuschak.org/My_morning_writing_practice][author's archived links]]; no other opaque note ID is exempt.

The exact HTTPS [[https://hemerotecadigital.bn.gob.ar/collection/001181802/critica][Biblioteca Nacional Crítica collection]] route is also registered:
its numeric identifier and hostname suffix otherwise resemble an opaque token.
The complete route also recognizes the collection page’s observed year links
(1914–1916 and 1919–1957). Other paths and payloads retain all checks.
The observed 8 September 1947 issue link also permits its exact =render.php=
file locator and collection selector. Other query fields, fragments and request
payloads stay scanned; repeated selector keys receive no projection.

The public =www.utorpheus.com/file/catalog/pdf_musiche/lb018.pdf= excerpt
and Galiciana’s =/recurso/caras-y-caretas-semanario-festivo-literario/UUID=
catalogue routes use complete HTTPS authority/path matching. Their query,

and decade range resemble an opaque token. Only that complete authority/path

=api.digitale-sammlungen.de= and complete =/iiif/presentation/v2/OBJECT/manifest=
route for numeric BSB identifiers, including the documented suffixed form.
Its full-size JPEG IIIF image route uses bounded numeric page identifiers.

The [[https://archive.org/developers/md-read.html][Internet Archive metadata API]] projects the fixed HTTPS
=archive.org/metadata/= prefix. A bounded =Caras_y_Caretas_Buenos_Aires_=
date/issue identifier grammar is additionally recognized, matching 2,112 public
search results. Its PDF and DjVu text download routes require the filename
stem to equal the item identifier, as verified in issue 1006 metadata. Other
identifiers and partial-read suffixes remain scanned, as do query/fragment
values, headers and bodies. Exact public routes also cover the observed 1909
Toronto volume metadata/OCR and 1929 year-end volume PDF/OCR. Literal =--get=
searches are parsed as requests;
=--data-urlencode= values retain payload scanning and output paths remain local.

Local-path projection preserves real newline, semicolon and =&&= command
boundaries; it does not quote them into inert arguments. Request payloads
remain scanned across every command in a sequence.
A closed =pdftotext= reader form accepts optional positive =-f= / =-l=
page bounds, one absolute PDF pathname and stdout. Only its local pathname
is projected; pipelines, wrappers, passwords and unknown options stay scanned.

The network heuristic treats dots and hyphens as part of names, so =curl.py=,
=curl-cffi= and =zotra-use-curl= do not activate it. Actual
=curl=/=wget=/=nc=/=ncat= names, including interpreter subprocess arguments,
retain the opaque-token scan. This does not exempt interpreter bodies or alter
known-secret checks. =tests/test_secret_guard_network_names.py= covers the
local wheel-provenance and installed-source reads, and unsafe controls through
both runtimes. Relative =./curl= and absolute =/usr/bin/curl= remain scanned.

The GitHub write guard is deny-only. It refuses writes outside the committed
repository registry, but a matching repository establishes only that boundary;
the hook emits no explicit allow, including for pull-request merges. Authorized
writes continue through the host's normal permission layer and still require the
user authorization called for by the global instructions.

The Elisp documentation gate may be deferred on a feature branch with
=branch.<branch>.deferDocUpdates=true= for a deliberate multi-commit refactor.
The setting is ignored on =main= and =master= and should be removed when the
branch merges. The Codex counterpart uses the same rule.

Elisp test and live evidence is recorded by the wrappers themselves and
checked by the global Git hooks in =claude/git-hooks= and the Stop hook, all
through =claude/bin/elisp-evidence=; no hook reads command text to decide what
was tested. This is not authentication against another process running as the
same user, which can write the user-owned state files under
=~/.local/state/agent-elisp-evidence/=. It prevents accidental skipping, not a
determined forger.  The Stop hook is registered in
=~/.claude/settings.json= as =~/My\ Drive/dotfiles/claude/bin/elisp-evidence
stop-check --agent claude=, and =core.hooksPath= in =~/.gitconfig= names
=~/My Drive/dotfiles/claude/git-hooks=.

The reasoning-worktree SessionStart hook repairs required key links before its
working-directory and origin checks. That repair loop therefore runs in every
session in every repository, so it must start no subprocess when all links are
already correct. It uses shell parameter expansion for the worktree name and the
=-ef= test for the already-correct comparison, instead of one =basename= and one
=readlink= process for each worktree. A link that reaches the canonical key
through a different path counts as correct and stays as it is; a missing,
broken, or foreign link is still repaired. For eligible worktrees it fetches and
merges shared state without pushing, reapplies the local overlay and context,
injects private project skills, and installs the worktree-local issue-comment
freshness guard. The bulk wrapper performs the shared fetch once. As best-effort
nonfatal maintenance, the hook also garbage-collects only clean, fully pushed
transient CR worktrees and prints the =cr-task-state --hook= branch, run, and
rubric-state banner with divergence warnings. Comment freshness blocks a post
when a newer reasoning-task issue comment has not been acknowledged and includes
that newest comment in the denial; API failures are an intentional fail-open
boundary. Codex has no SessionStart counterpart and routes this posting flow to
Claude.

The LaunchAgent registry guard routes every launchd change through
=~/repos/launchd=. It denies writing a plist into
=~/Library/LaunchAgents=, redirecting into that directory, and
=launchctl bootstrap/load/enable/submit= as well as
=bootout/unload/disable/remove=, and names =bin/launchd-install.py= in the
denial. That script writes the canonical plist, symlinks the live file, adds the
=registry/jobs.json= entry, and runs the drift audit; loading stays behind its
explicit =--load= flag. Read-only inspection is deliberately untouched: =ls=,
=cat=, =readlink=, =diff=, =plutil -p=, =defaults read=, and =launchctl
print/list=. Heredoc bodies are masked so a commit message quoting a live path is
not read as an invocation. =ALLOW_LAUNCHAGENT_CHANGE=1= is the narrow override
for a change Pablo has authorized, such as a temporary bootout while debugging.

The secret guard also checks process-listing commands before its permissive
branches. On macOS, =pgrep -fl= can expose credentials in process arguments;
=ps= default/full formats and environment output have the same risk. The
paired =lib-process-output-policy.py= permits PID-only =pgrep=, name-only
=pgrep -l=, and explicit safe =ps= fields. Pipes and redirects do not exempt
unsafe listings. Literal wrappers, shell substitutions and compound commands
are checked; relevant interpreter source that cannot be classified is denied.
Computed executable names and external script contents are outside this
static guard's coverage. The policy is not a general output redactor.
Quoted Python-stdin heredocs distinguish ordinary =ps= / =pgrep= variable
names from process inspection. Calls, attribute bases, imports, literals,
=psutil= and =/proc= markers remain checked; unquoted heredocs stay conservative.
=tests/test_process_output_policy.py= and =tests/test_process_output_guard.py=
cover the policy and registered guard entry points with synthetic commands.
