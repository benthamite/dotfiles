#+title: Codex hook implementations
#+author: Pablo Stafforini

Before changing any secret-protection hook, read
[[file:../../docs/secret-guard.md][docs/secret-guard.md]]: the incident inventory, the
rules for changes (no new per-site exemptions) and the approved redesign.
Run =bin/test-guards= (all guard tests in parallel) before committing a guard
change.

The closed Python document-edit classifier permits =update= statements on bound
JSON data with one validated dictionary literal and no keyword arguments.
A mutation alone does not satisfy its required document write.

Literal Python-file writers have a separate closed shape: one literal path and
source, an optional existence guard, mode =0600=, and path-only print. The
generated source is parsed with both writer exemptions disabled. Credential
references, unknown calls and additional writes remain denied.

* Guard engine

Every PreToolUse guard runs in one Python process: =agent-guard.sh= starts
=lib/python/agent_guard= (=engine.main= with runtime =codex=), which parses the
payload once, normalizes Codex's object-or-string =tool_input=, and runs the
policies registered for the tool. Each former guard hook is a module in
=lib/python/agent_guard/policies/=, and =engine.py= holds the per-tool chains in
the order the old registrations ran. The shell tools (=Bash=, =exec_command=,
=functions.exec=, =functions.exec_command=) run =sensitive_read=, =secret_leak=,
=ahrefs=, =github_write=, =destructive=, =walk_list=, =elpaca_rebuild=,
=dirty_tree=, =launchagent=, =untrusted_execution=, =hookspath=,
=retired_secrets= and finally =codex_wrap=; =apply_patch=, =Edit= and =Write=
run =secret_leak=, =elpaca_dotfiles_edit=, =texi_edit=, =walk_list=,
=launchagent= and =retired_secrets=. A denial from any policy denies, with the
reasons joined in chain order.

=agent_guard.codex_payload= and =agent_guard.codex_paths= are the engine's
ports of =lib-codex-hook-json.sh= and =lib-codex-paths.sh=, which stay here for
the remaining shell hooks. The Python classifiers the guards use
(=lib-op-policy.py=, =lib-process-output-policy.py=,
=lib-function-body-policy.py=, =lib-inert-mentions.py=,
=lib-untrusted-execution.py=) now exist once, in =claude/hooks/=, and are
imported in-process through =agent_guard/classifiers.py= for both runtimes.
Patterns the shell guards gave to =grep -E= and =sed -E= are evaluated by
=agent_guard/ere.py=, which reproduces the BSD tools' semantics.

=codex_wrap= routes credential-prone shell commands (the same rule as Claude's
output wrapping) through =claude/hooks/redact-secrets.sh= by returning an
=updatedInput= with an explicit allow. This also masks output streamed from a
still-running =exec_command= session and results Codex marks as errors, which
=redact-tool-output.py= cannot reach. The exit status is preserved.

The guard fails closed: =engine.main= denies on any exception or malformed
payload, and =agent-guard.sh= turns every exit status other than 0 into exit 2,
so a missing interpreter, a broken import or a crash blocks the call. Where
the engine deliberately decides differently from the shell guards it replaced,
the difference is listed in =docs/plans/2026-10-01-guard-engine.md=.
=bin/test-guards= runs the guard tests in-process through
=tests/guard_harness.py=, plus a few end-to-end runs of =agent-guard.sh=.

* Activation and boundaries

The tracked [[file:../hooks.json][hooks.json]] file registers Codex hooks and is live globally through
the =~/.codex/hooks.json= symlink. Registration and implementation are separate:
the JSON chooses an event and matcher, while the scripts in this directory
decide what to block, record, regenerate, or report. The five =lib-*= files are
helpers rather than registered hooks. =session-learning-capture.sh= is
a retained legacy helper and is not registered at present.

These hooks supplement the written instructions with executable checks. An
allowing result from one hook does not bypass another hook, the global rules,
or the need for user authorization.

* Operational contracts

The untrusted-execution policy (=agent_guard.policies.untrusted_execution=)
runs for the shell tools and uses the =lib-untrusted-execution.py= classifier
in =claude/hooks/=. Each literal nested
=functions.exec= command retains its own workdir; ambiguous contexts deny.
The classifier denies recognizable transient package runners, downloaded
interpreter input, and host execution involving
=~/.local/share/agent-untrusted/=. Plain source inspection and package metadata
remain available. The canonical =bin/untrusted-run= command is allowed per
invocation; its host substitutions and following commands remain checked.
A variable executable assigned once, unconditionally, to a literal earlier in
the same command (=F=/path; "$F" ...=) is classified as that literal.
Quoted data heredocs are distinguished from shell commands. Unsupported
relevant shell forms deny without an approval prompt. This is bounded routing,
not arbitrary-program analysis or an independent same-user security boundary.
The VM runner supplies the execution boundary. Synthetic hook decisions are
covered by =tests/test_untrusted_execution_guard.py=. A changed hook definition
in =hooks.json= also needs native Codex trust before it becomes effective.

Every guard policy converts an unexpected failure into a denial: an exception
denies the call ("Security hook failed; tool execution denied."). Ordinary
successful checks retain their allow/deny decisions and never introduce
approval prompts.

The secret guard (=agent_guard.policies.secret_leak=) scans =Write.content= and
=Edit.new_string= as well as patch text. Secret-file exceptions apply independently to each patch destination;
an exempt addition, update, deletion, or move never exempts another file.
Ordinary-file patch sections retain scanning of their complete text. Moving a
secret file to an ordinary destination is denied because unchanged contents
are absent from the patch; no target file is read. Malformed patch framing
also denies. =tests/test_codex_secret_patch_guard.py= exercises these decisions
without applying patches.

The destructive-command guard (=agent_guard.policies.destructive=) decides allow
or deny, never an approval prompt; =ALLOW_CLONE=1= is the narrow explicit clone
override.

The dirty-tree rewrite guard (=agent_guard.policies.dirty_tree=) blocks =filter-repo= and =filter-branch= only when
the target repository has staged or unstaged tracked changes. Untracked files
are deliberately ignored. It resolves =git -C= and the last applicable =cd=
before falling back to the hook working directory, and masks heredoc bodies to
avoid prose false positives. =ALLOW_DIRTY_REWRITE=1= is the explicit override.

The sensitive-read guard (=agent_guard.policies.sensitive_read=) denies content
access to credential-bearing paths. It
permits content-free metadata, quiet/count/name-only searches, existence tests,
Git ignore/index queries, and auth-aware tools only in recognized narrow forms.
The classifier recognizes =git-crypt=, =security=, =op=,
=op-automations=, and =op-desktop= as auth-aware tools; the independent
secret-leak guard still denies their secret-printing shapes. It also permits
=.env= or =.envrc= to be sourced solely as subprocess environment, and
=op-automations run --env-file .env.op -- <program>= with leading =VAR=value=
assignments and file redirects, while still denying commands that print,
parse, or dump that environment.

The secret-leak guard applies the same command policy to every literal nested
=cmd= inside a =functions.exec= program, including nested shell-tool calls; a
1Password broker named anywhere else in the program is denied as
unclassifiable. Raw =op=, =security=, and =pbpaste= are denied even
when wrapped, piped, filtered, redirected, dynamically resolved, or called
through a literal nested shell. The brokers =op-automations= and =op-desktop=
are classified by =lib-op-policy.py= (in =claude/hooks/=), an allowlist of command shapes whose
stdout carries no credential: masked =run= with a non-shell program, =read=
captured into a variable, a regular file, or a listed consumer, item output
piped to a metadata-only =jq= filter or a file, =document get=/=inject= with
=--out-file=, writes without =--format=, =op-desktop item share= restricted
with =--emails=, and metadata commands. Every other broker shape is denied,
including =--reveal=, share links without =--emails=, =signin=,
=environment read=, credential-minting subcommands, indirection, and any
=OP_*= environment override. Quoted literals in ordinary commands and simple
non-expanding =echo=/=printf= documentation remain available. Interpreter
source is never parsed as shell text: a Python heredoc naming a broker is
denied unless the broker mode of =lib-python-heredoc.py= recognizes it as a
pathlib document edit, and any other interpreter program naming a broker is denied.
The case table is =tests/test_op_policy.py=.

The opaque-token heuristic no longer denies (intended difference 3 of
=docs/plans/2026-10-01-guard-engine.md=). Where it would have been the only
reason to deny, =agent_guard.url_heuristic= appends one line naming the
runtime, tool and a fixed label, never the value or the command, to
=~/.local/state/agent-guard/heuristic.log=. Its classifier is the former
=lib-public-url-scan.py= without the verified-route registry, which existed
only to exempt public URLs from the denial: only URL operands of recognized
literal =curl=/=wget= commands are parsed, headers, bodies, filenames and URL
tails stay scanned with bounded percent decoding, and local read paths are
projected first. Known values and prefixed token shapes still deny.
=tests/agent_guard/test_url_heuristic.py= pins the parser boundaries.

The quote-aware network parser classifies literal =curl=/=wget= output-file
options itself. A quoted URL query containing =&= cannot turn its separate local
destination into a network payload. URI-shaped output values, headers, bodies,
URLs and unknown command forms remain scanned; known-secret checks still inspect
the complete original command.

Literal newline command separators and backslashes inside single quotes are
parsed without evaluating shell text. Literal =mkdir -p= absolute directories
are local destinations when no pipeline can forward diagnostic output.
Expansions, unquoted or double-quoted escapes, and unknown command forms retain
conservative scanning.

The [[https://github.com/internetarchive/wayback/tree/master/wayback-cdx-server][Wayback CDX API]]'s single =url= target and HTTPS =web.archive.org/web/=
replay URLs with a 14-digit timestamp and optional =id_= flag are parsed as
archive envelopes. Their embedded targets still pass the ordinary URL checks;
malformed decoded targets and nested archive envelopes receive no exemption.
Other query fields, fragments,
headers and bodies remain scanned.

Literal =curl --get= searches are parsed as requests; =--data-urlencode=
values retain payload scanning and output paths remain local.

Local-path projection preserves real newline, semicolon and =&&= command
boundaries; it does not quote them into inert arguments. Request payloads
remain scanned across every command in a sequence.
A closed =pdftotext= reader form accepts optional positive =-f= / =-l=
page bounds, one absolute PDF pathname and stdout. Only its local pathname
is projected; pipelines, wrappers, passwords and unknown options stay scanned.

A terminal quoted =cat > literal.md/org/txt/json= heredoc is document data
for network-command detection. Pipes, continuations, extra commands, unquoted
bodies and executable destinations remain conservative. If a network marker
exists elsewhere, the full original command is scanned; known-secret checks
always retain the original bytes. This is a lexical boundary, not a filesystem
or shell-rebinding sandbox.

Quoted Python stdin may use =curl=, =wget=, =nc= or =ncat= as ordinary data
variables without activating network detection. Callable/attribute receivers,
imports, literals and unsupported source remain scanned. This projection only
controls activation; actual network markers still trigger inspection of the
original payload, and known-secret checks always retain the original bytes.

The network heuristic treats dots and hyphens as part of names, so =curl.py=,
=curl-cffi= and =zotra-use-curl= do not activate it. Actual
=curl=/=wget=/=nc=/=ncat= names, including interpreter subprocess arguments,
retain the opaque-token scan. This does not exempt interpreter bodies or alter
known-secret checks. =tests/test_secret_guard_network_names.py= covers the
local wheel-provenance and installed-source reads, and unsafe controls through
both runtimes. Relative =./curl= and absolute =/usr/bin/curl= remain scanned.
For a recognized literal =functions.exec= wrapper, Codex uses the decoded shell
command for both activation and scanning; JavaScript newline escapes cannot
conceal a following network command.

The GitHub write guard (=agent_guard.policies.github_write=) is deny-only. It refuses writes outside the committed
repository registry, but a matching repository establishes only that boundary;
the hook emits no explicit allow, including for pull-request merges. Authorized
writes continue through the host's normal permission layer and still require the
user authorization called for by the global instructions.

The Elisp commit gate routes each literal nested =tools.exec_command= call by
its own =workdir=, groups staged and commit calls by repository, inherits an
omitted workdir from the outer context, and denies dynamic or ambiguous commit
targets. The post-commit tracker uses the same context and recognizes Git
global options such as =-C=. Multiple commits inside one shell call remain
distinct. Inert quoted text and shell comments do not count as commits, while
interpreter payloads remain conservative. Only evidence whose label matches
exactly one supported wrapper in executable position, with no other executable
in that command event, can clear an obligation.

Elisp test and live evidence is recorded by the wrappers themselves and
checked by the global Git hooks in =claude/git-hooks= and the Stop hook, all
through =claude/bin/elisp-evidence=; no hook reads command text to decide what
was tested. This is not authentication against another process running as the
same user, which can write the user-owned state files under
=~/.local/state/agent-elisp-evidence/=. It prevents accidental skipping, not a
determined forger.

The Elisp documentation gate honors
=branch.<branch>.deferDocUpdates=true= only on feature branches and ignores it
on =main= and =master=. Remove the setting when the branch merges.

The hook installer owns all eight =codex-hook-wrapper= lifecycle registrations.
It must preserve the live =config.toml= and =hooks.json= symlinks and replace
stale profile-specific wrapper paths rather than append duplicates. The global
wrappers are safe outside Emacs: when =CODEX_BUFFER_NAME= is absent, they
consume the payload and exit successfully without calling =emacsclient=.

=require-codex-readme-update.sh= is a dotfiles-scoped commit gate. Its
command-text fallback excludes project-local =.codex/= paths, its staged-file
check excludes the project-local =.codex/skills/= mirrors that
=ai-config-sync guard-commit= checks, and it excludes
the repo-root =AGENTS.md= project mirror; the project-local dotfiles skill is
handled by its configured documentation owner instead.

The LaunchAgent registry guard (=agent_guard.policies.launchagent=) routes every launchd change through
=~/repos/launchd=. It denies writing a plist into
=~/Library/LaunchAgents=, redirecting into that directory, and
=launchctl bootstrap/load/enable/submit= as well as
=bootout/unload/disable/remove=, and names =bin/launchd-install.py= in the
denial. That script writes the canonical plist, symlinks the live file, adds the
=registry/jobs.json= entry, and runs the drift audit; loading stays behind its
explicit =--load= flag. Read-only inspection is deliberately untouched: =ls=,
=cat=, =readlink=, =diff=, =plutil -p=, =defaults read=, and =launchctl
print/list=. Heredoc bodies are masked so a commit message quoting a live path is
not read as an invocation. =ALLOW_LAUNCHAGENT_CHANGE=1= is the narrow override
for a change Pablo has authorized, such as a temporary bootout while debugging.

The secret guard also checks process-listing commands before its permissive
branches, including every extracted literal =functions.exec= shell command.
On macOS, =pgrep -fl= can expose credentials in process arguments; =ps=
default/full formats and environment output have the same risk.
=lib-process-output-policy.py= (in =claude/hooks/=) permits PID-only =pgrep=, name-only =pgrep -l=,
and explicit safe =ps= fields. Pipes and redirects do not exempt unsafe
listings. Literal wrappers, shell substitutions and compound commands are
checked; relevant interpreter source that cannot be classified is denied.
Computed executable names and external script contents are outside this
static guard's coverage. The policy is not a general output redactor.
Quoted Python-stdin heredocs distinguish ordinary =ps= / =pgrep= variable
names from process inspection. An empty list with one binding in its own
module or function scope may use =append=. Parameters, rebinding, closure
receivers, =global=/=nonlocal= and dynamic namespaces remain conservative.
Indexed =read_text()= calls are also recognized for
uniquely bound lists from literal =pathlib.Path= joins and =glob= patterns;
shadowed builtins/imports, dynamic receivers and mutations remain conservative.
Other calls/attribute bases, imports, =psutil= and =/proc= markers remain
checked; unquoted heredocs stay conservative. String literals are data only
when the program imports nothing beyond a fixed set of inert modules and names
no evaluator (=eval=, =exec=, =compile=, =getattr=, =__import__= ...); f-string
parts always stay checked. A quote is a word boundary, so =f'ps'= counts as
=ps=. A heredoc operator after =#= may be a comment, so its "body" is treated
as shell.
=tests/test_process_output_policy.py= and =tests/test_process_output_guard.py=
cover the policy and registered guard entry points with synthetic commands.

The secret guard also denies shell introspection that would print a shell
function's body. On 2026-09-30 =which NAME= printed a zsh function (zsh
=which= is =whence -c=) whose body held literal Google OAuth credentials, and
the output redactor knew neither shape.
=lib-function-body-policy.py= (in =claude/hooks/=) denies =functions=, =typeset/declare -f= and the
=$functions= parameter outright, and =which=, =where=, =whence -c/-f/-x= and
=type= when a named word is a shell function; it asks a zsh child =whence -w=,
which prints only each name's kind. =whence -w=, =type -w=, =command -v=,
=functions += and =${(k)functions}= stay available, as do lookups of
commands and paths. Wrappers, substitutions, =sh -c=, =eval= and shell-fed
heredocs are checked; other heredoc bodies are data. A classifier failure
denies. =tests/test_function_body_guard.py= covers the policy, the guard entry
points, the Google OAuth shapes (=GOCSPX-= client secrets, =1//= refresh
tokens, =ya29.= access tokens) in the input guards and the redactor.

* File index

|------+---------|
| =agent-guard.sh= | The only PreToolUse guard registration: runs the guard engine (=lib/python/agent_guard=) and turns every exit status other than 0 into exit 2, so a missing interpreter, import error or crash denies. |
| =lib-codex-hook-json.sh= | Normalizes Codex hook payloads, including block-array responses from =functions.exec=, extracts literal command/workdir records without evaluating JavaScript, preserves valid UTF-16 pairs and rejects unpaired surrogates/NULs, recognizes Git global options, and recovers an exact nested Bash command's parent workdir from its transcript. Used by the remaining shell hooks and the shared Git classifier; the guard engine uses its port, =agent_guard.codex_payload=. |
| =lib-codex-paths.sh= | Extracts changed paths from the supported Codex edit and patch payload forms for the remaining shell hooks; the guard engine uses its port, =agent_guard.codex_paths=. |
| =lib-python-heredoc.py= | Classifies narrowly recognized quoted Python stdin bodies before excluding them from outer-shell lexical scanning. Consecutive supported heredocs are classified in order; unknown shell structure stops that scan. A control operator or output redirection after the delimiter on the header line (=| head -3=, =2>&1=, =&& …=) leaves the heredoc recognized and stays in the outer-scanned shell text; a document edit requires no such suffix. Parsed =pass= statements and a closed text/JSON document-edit language are exempt from protected-name checks. Document edits require one standalone direct Python heredoc with validated imports, data bindings and calls; Codex additionally requires one complete literal exec wrapper. Unknown/dynamic/multi-call shapes retain conservative scanning. Unsupported source stays unmasked and other secret checks retain original input. The shared Git classifier separately neutralizes shell-substitution markers in valid quoted Python bodies while retaining the rest of the source; Python data without standalone Git/commit references cannot fabricate a shell substitution or an ambiguous commit. Git-bearing interpreter source retains conservative scanning because subprocess calls may execute its strings. Not a Python sandbox. |
| =lib-repo-root.sh= | Resolves the effective Git repository from structured hook context, Git global options, or an exact unambiguous parent =functions.exec= record without shell re-evaluation. |
| =lib-staged-files.sh= | Lists proposed commit paths and name-status data, including explicit path selections and the complete amended commit. |

The documentation audit requires every tracked direct child to appear exactly
once in this table. After changing a registered hook, verify the registration
and exercise the relevant allow and deny paths; running the script in isolation
does not prove that Codex invokes it with the intended event payload.
